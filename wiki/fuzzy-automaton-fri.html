The behaviour-control architecture of the Hungarian ethorobotics programme, developed by Kovács and Vincze at Miskolc (kovacs-fri-automaton-series). Distinct from — and never integrated with — the Szabó emotional engine.

Why a fuzzy automaton

Ethological models are descriptive verbal models: sparse action–reaction rules observed over event sequences, with states that are continuous (mood, anxiety) and only partially observable. That demands, simultaneously:

  • rule-based knowledge representation (rules are what ethologists produce),
  • state-machine structure (behaviour follows observed sequences),
  • continuous values and states.

A fuzzy automaton satisfies all three: the state is a vector of membership values, state transitions are governed by a fuzzy rule base, observations and conclusions are continuous.

Formally, extending the Fuzzy Finite-state Automaton to continuous inputs:

F̃ = (S, X, P, Y, δ, ω)
  S  finite set of fuzzy states        X  input vector
  P  fuzzy start state                 Y  output vector
  δ: S × X → S   fuzzy state-transition function
  ω: S × X → Y   output function

The rule-base explosion, and FRI

A classical fuzzy rule base for δ is exponential:

R = n · iⁿ · jᵐ

(n = state-vector length, m = input dimension, i, j = term-set sizes). For an ethological model of 10–20 state variables that means thousands of rules — while the actual ethological knowledge amounts to a few dozen. Most rules would be undefined, which classical fuzzy reasoning cannot handle.

Fuzzy Rule Interpolation (FRI) removes the problem: the rule base may be sparse, and FRI still produces a reasonable interpolated conclusion when no rule fires under the current observation. Only the significant rules need to exist.

FIVE (the method used) adopts the Vague Environment concept: fuzzy partitions are handled by scaling functions, which turns fuzzy interpolation into crisp interpolation, then applies Shepard-operator interpolation for cheap multidimensional evaluation. Available as a MATLAB FRI Toolbox.

The two properties that matter for this thesis

Low computational demand — the authors repeatedly claim the structure is "quick enough to fit the requirements of real-time embedded applications". Never benchmarked in any paper in the corpus, but the claim is architectural, not empirical, and plausible.

Human-readable rules — "even after numerical optimization of the model, the rules are still human readable, and helps the formal validation of the model by the ethological experts". This is a genuine advantage over a learned controller and is the strongest argument against replacing this layer with reinforcement learning.

The argument is weakened but not defeated

rl-for-behaviour-learning records the decision to learn the behaviour layer, and answers this objection by keeping the ethologically-authored primitives as the admissible action set A(s) (sutton-barto-2018-rl §14.3) rather than replacing them. Legibility survives in the action set.

What does not survive is this page's other contribution: the fuzzy automaton encodes observed behavioural sequences — δ: S × X → S is a hand-authored model of how dogs move between states. A learned policy replaces exactly that. So the honest position is that RL costs the sequencing grounding while preserving the primitive grounding, and the thesis should say so. Q9 and Q11 in open-questions.

A state machine is the wrong substrate for a learned layer

colledanchise-ogren-behavior-trees measured GP-BT against an FSM-based learner on the Mario AI benchmark: "the FSM approach generates a number of nodes that increases exponentially over time, while the growth rate in GP-BT tends to decrease" (§8.2.4.1). §2.6 gives the analytic reason — "a FSM with a large number of transitions can drastically deteriorate the speed of an algorithm that has to consider all the possible paths in the FSMs" — and traces it to transitions being one-way control transfers, Dijkstra's goto.

A fuzzy automaton is a state machine. Its transition function is exactly what a learned policy would replace, and it is the part that scales badly under learning. So the two objections converge: the automaton loses its distinctive contribution to the learner and is a poor substrate for one.

What the automaton still has and a BT does not is behaviour fusion — continuous blending by necessity level, which can express "somewhat anxious while still exploring". A tick selects; it does not blend. That loss is real and unresolved. See behaviour-trees and Q9.

Behaviour-based control

The output function ω: S×X→Y decomposes into parallel component behaviours plus behaviour fusion, giving the standard behaviour-based control structure — behaviour coordination (which behaviour, or what necessity level for each) and behaviour fusion (how to blend them).

Relationship to behaviour trees

This decomposition does the same job as a behaviour tree but with fuzzy blending rather than discrete branching. py_trees on robot-platform arbitrates discretely. Whether to reimplement the fuzzy automaton inside a behaviour tree, run them in parallel, or drop one is an open architectural decision — Q9 in open-questions.
