Csenge's own package (hubaycsenge/mecanumbot_behaviours), clipped 2026-07-28. High-level behaviour orchestration on py_trees / py_trees_ros.

The previous clip established only that this repository existed. It turns out to contain an experiment design, already implemented — which changes what validation-study has to build.

Structure

Package Purpose
mecanumbot_behaviours Meta package (ament_cmake), dependency aggregation only
mecanumbot_leading_behaviour Behaviour trees for the leading / attention-guidance experiments; holds the reusable behaviour library
mecanumbot_demo_behaviours Demo trees (wander between people, hide and seek) reusing the leading library

How it drives the robot

The trees do not drive the wheels for navigation. They publish Nav2 goals on /goal_pose and watch /navigate_to_pose/_action/status, using /cmd_vel only for in-place spins. Accessory gestures go on /cmd_accessory_pos; LEDs go through the set_led_status service.

That is a clean layering — deliberation in the tree, motion planning in Nav2 — and it matches option 3 on behaviour-trees (tree as executor), which is also the option rl-for-behaviour-learning selects.

The three experimental conditions

Condition Node Signalling channel
Control control_leading_bt_node None — navigation only
Doglike doglike_leading_bt_node Neck / gripper gestures on /cmd_accessory_pos
LED LED_leading_bt_node LED patterns via set_led_status

Plus bottom_up_tree_node, a simpler baseline combining approach with LED indication, run directly with ros2 run.

This is a within-subject signalling-modality experiment, already coded

validation-study inherited its protocol from lakatos-2014-emotion-attribution and gacsi-2016-emotion-attribution but had no implemented conditions. Here they are: a no-signal control and two distinct expressive modalities, on the same navigation substrate.

This maps directly onto the leading behaviour of lakatos-2014-embodiments-demo — the hearing-dog scenario with its four components (interaction initiation, leading, feedback, goal-oriented attention-directing). The condition structure isolates which expressive channel carries the leading signal, which is precisely the open question raised by robot-platform having no face.

But note what it is not. These are three fixed signalling conditions, not an emotional engine. There is no affect model here, no arbitration, no learning. The comparison it supports is "does the dog-like channel beat LEDs and beat nothing at leading a person", which is a legibility question — valuable, and already a paper, but not the thesis claim in emotion-engine. Do not let the wiki blur the two.

Condition selection is by launch argument, defaulting to Doglike. The launcher picks a parameter YAML from the current Wi-Fi SSID (nmcli, falling back to iwgetid): MecanumNet → behaviour_setting_constants.yaml, MecanumetoNet → Eto_behaviour_setting_constants.yaml. Two named settings files implies two physical environments — worth knowing which, for the "real environment" part of Q3.

What it consumes

people_fusion from mecanumbot-perception, plus subject_pose from the lidar detector for the leading behaviours. Runtime dependencies are py_trees, py_trees_ros, rclpy, geometry_msgs, action_msgs, nav2_msgs, mecanumbot_msgs; mecanumbot_demo_behaviours imports directly from mecanumbot_leading_behaviour, and its utils/map_generate.py also needs opencv-python and mecanumbot_description.

Known problems in the package

  • Runtime dependencies are not declared in either package.xml — they list only lint test dependencies. The packages build, but rosdep will not install what they need to run. Same issue as mecanumbot-perception.
  • tree_nodes/hide_and_seek.py is present and complete but has no entry point in setup.py, so it is not installed as an executable.
  • mecanumbot_demo_behaviours ships a copy of the launch file that still points at doglike_demo_bt_node / control_demo_bt_node / LED_demo_bt_node, none of which are registered in that package's setup.py. Demo trees must be started with ros2 run.

Hide and seek, and wander between people

The two demo trees are more interesting than "demo" suggests.

Wander between people is an attention/proxemics behaviour over the fused people array. Hide and seek is a game — and games are, in miklosi-2017-ethorobotics' terms, exactly where social-competence is built. It is also the only behaviour in the whole corpus that requires modelling what the other party can perceive.

That it is written but not installed is worth asking about — it may be abandoned, or it may be the next experiment. Ask Csenge. #needs-source
